# Gate 6B.1 cross-platform frozen evidence

The certified database-only integration candidate exposed a platform defect in the legacy evidence format, not a database-artifact change. The historical JSON manifest recorded bytes from a Windows checkout, while Git stores canonical blob bytes. A fresh Windows worktree therefore reported 148 historical mismatches even though its protected Git objects matched certified source commit `87524f872e76f24de631d1cbf58580674c9df2a9`.

## Byte evidence

The 414 migration entries divide into 178 whose recorded SHA-256 equals the canonical Git blob, 231 whose recorded SHA-256 equals a full CRLF checkout, and five whose recorded SHA-256 equals the canonical LF body with only the final newline changed to CRLF. The five mixed-final-newline paths are:

- `supabase/migrations/20260301101500_tongs_recording_session_items.sql`
- `supabase/migrations/20260302110000_tongs_barstock_projects_and_links.sql`
- `supabase/migrations/20260303020000_tongs_workspace_team_rpcs.sql`
- `supabase/migrations/20260303023000_tongs_workspace_team_list_rpcs.sql`
- `supabase/migrations/20260303030000_tongs_workspace_team_hardening.sql`

The same working-copy hashing defect affected `supabase/tests/catalog/post_slice_a_contract_rows.sql` and `scripts/lib/ForgeGate5D.psm1`. Both canonical Git blobs match the approved frozen hash; their Windows checkout bytes did not. Repository configuration was `core.autocrlf=false`, `core.eol` unset, and the prior catch-all attribute was `* text=auto`. The discrepancy was retained from the source evidence rather than generated by the current checkout.

The legacy expected hashes remain unchanged as historical evidence. `scripts/verify-frozen-git-evidence.mjs` now establishes authority by comparing path, mode, and blob object ID in current `HEAD` with the certified source tree, then hashes the raw blob bytes. It also classifies every legacy expected hash as canonical blob, full-CRLF checkout, final-CRLF checkout, or rejects it as unexplained.

## Fail-closed and execution contracts

Git-object authority rejects a missing source object, wrong tree, wrong branch object, unsupported mode, staged content, semantic unstaged content, case collision, protected-root untracked content, and custom filters or working-tree encodings. Git's clean filter is used only to detect whether an LF/CRLF checkout represents the same content; it is not treated as execution-byte identity.

Before migrations or frozen SQL tests execute, `scripts/materialize-frozen-git-evidence.mjs` verifies the tree and index and then writes the exact current-HEAD blob bytes. A second verification with `--require-exact-worktree-bytes` proves that the runtime will consume those bytes. The protected database/evidence paths are narrowly marked `-text`; unrelated application paths keep the repository's existing line-ending policy.

The canonical verifier is the front door for the historical manifest, B1, and pre-Slice-A checks. The byte-frozen Gate 5D verifier remains unchanged and is run only after explicit materialization. Runtime lineage validation additionally requires exact canonical bytes for the historical root. Generation utilities that intentionally hash newly generated output remain working-file checks and are not frozen-source authorities.

## PR trigger finding

The existing `.github/workflows/pr-smoke.yml` automatically enables `smoke:team` and `smoke:hearth-phase4` whenever their repository secrets exist. Those jobs receive service-role or access credentials, and their smoke/fixture code creates, updates, and deletes hosted Auth and application records. There is no changed-path exclusion for a database-only PR.

Gate 6B.1 did not modify or enable the hosted smoke workflow. Gate 6C subsequently removes these jobs from ordinary PR execution and isolates them behind a manual, protected, trusted-main-only path. See [Gate 6C PR hosted-write isolation](../v1-gate6c/PR_HOSTED_WRITE_ISOLATION.md) for the implemented contract and remaining external owner checks.

## Regression coverage

`scripts/test-frozen-git-evidence.mjs` creates a small independent temporary repository and tests LF, CRLF, mixed-final-newline evidence, staged-only and unstaged changes, untracked protected paths, missing source objects, different-branch objects, wrong verified-tree selection, and the distinct exact-runtime-byte gate. `.github/workflows/database-frozen-evidence.yml` reproduces this contract on Ubuntu without secrets or hosted services. Its Ubuntu status is only established when GitHub Actions executes it; local static validation is not a live Ubuntu pass.
