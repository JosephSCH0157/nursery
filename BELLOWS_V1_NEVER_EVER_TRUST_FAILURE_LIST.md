# Bellows V1 Never Ever Trust Failure List

This document defines the Bellows trust failures that must never occur.

Purpose:

These are the mistakes that destroy trust and reputation immediately.

## Bellows Must Never

### Record Without Visible Consent

No hidden capture. Ever.

### Lose A Completed Recording Silently

If data loss occurs, users must know immediately.

### Say Safe When Data Is Not Actually Safe

False reassurance destroys trust permanently.

### Leak Private Overlays Into Output

Scripts, warnings, prompts, and backstage information must remain backstage.

### Allow Unauthorized Entry Into A Session

Unexpected people appearing in a session is a catastrophic trust failure.

### Expose Credentials Or Stream Keys

Even a single exposure is unacceptable.

### Mix Sessions Accidentally

Cross-session data leaks are fatal.

### Require Technical Expertise Mid-Show

Users cannot debug while performing.

### Fail Without Explanation

Silence creates panic and speculation.

### Corrupt Recordings During Upload Or Processing

Integrity must be preserved ahead of speed or convenience.

## Canonical Trust Principle

Users must feel safer using Bellows than not using it.

## Why This Matters

Security and trust failures do not merely break software.

They break reputation in front of:

- audiences
- guests
- clients
- collaborators
- sponsors

Bellows therefore needs a trust bar appropriate to a production system, not a casual communications app.
