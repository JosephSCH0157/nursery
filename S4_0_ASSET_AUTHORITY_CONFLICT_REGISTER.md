# S4-0 Asset Authority Conflict Register

Status: migration-hotspot register. No entry is resolved by renaming in S4-0.

| ID | Conflict | Evidence | Current danger | Required disposition before migration |
| --- | --- | --- | --- | --- |
| S4C-001 | `asset_id` means both `tongs.assets.id` and a Hammer-local/path-derived ID. | `HammerVisualAsset.asset_id`; `deriveStableHammerVisualAssetId`; legacy placement migration. | A synthetic ID can masquerade as durable Tongs media. | Split semantics by provenance; classify existing rows individually. |
| S4C-002 | Hammer `asset_ref` can equal asset ID, path, storage key, or another opaque ref. | Placement contract requires `asset_ref`; legacy migration uses it as an identity seed. | A locator can authorize placement as though it were identity. | Keep compatibility field explicit; prohibit it from satisfying canonical readiness. |
| S4C-003 | Placement identity can seed media identity. | Legacy fallback `placement:<placement_id>` then stable-ID hash; default `clip_${asset_id}` in reverse direction. | Identity and placement become circular. | Preserve both historical values but brand/classify them separately. |
| S4C-004 | Image Map selection and candidate availability are conflated. | Hammer prefers selected candidate but falls back to `candidate_assets[0]`. | An unselected alternate becomes production media. | Remove fallback in implementation slice; unresolved selection must remain unresolved. |
| S4C-005 | Package projection can look canonical without canonical evidence. | Compatibility adapters fabricate empty bucket/key and construct `selected_asset` from entry candidate data. | Object shape is mistaken for relationship validation. | Require a server-issued authority/readiness result. |
| S4C-006 | Hammer local asset-array membership is treated as media validity. | Timeline persistence validates `clip.asset_id` only against local `assets[]`. | Cross-workpiece or legacy-derived IDs can survive reload. | Add canonical resolution state and relationship evidence; local membership remains structural only. |
| S4C-007 | Intro/outro `assetId` may be canonical or path-derived. | Candidate builder falls back to `deriveStableHammerAssetIdFromPath(file.path)`. | Packaging intent can contain a canonical-looking synthetic ID. | Classify candidate provenance; new writes require canonical ID. |
| S4C-008 | `selected_asset_id` has different authority strength across domains. | Current Tongs Image Map/B-roll/Reference RPCs validate it indirectly; older episode-package fields and helpers do not. | Same name implies guarantees that are not universal. | Inventory by writer/version; do not bulk-cast historical values. |
| S4C-009 | `candidate_revision_id` and canonical `asset_id` are both used as “the selected visual.” | B-roll/Reference selection tables select candidate revisions; clients expose candidate and asset IDs as strings. | Purpose/revision identity can be passed where media identity is expected. | Public contracts must carry both fields with distinct types. |
| S4C-010 | Script derivative basis is strong in newer DB tables but partial in legacy package/Hammer records. | New plans carry approval ID/revision/hash; legacy timeline migration creates null/unresolved script evidence. | Valid media may be presented as fresh for the wrong approval. | Freshness and asset readiness must be separate validation results. |
| S4C-011 | Content hash is copied into derivative rows but not universally checked at read/use time. | B-roll candidates and thumbnail v3 copy asset hashes; Hammer visual assets omit canonical hash. | An ID/evidence contradiction can go undetected downstream. | Canonical resolver returns authoritative hash and compares optional expected evidence. |
| S4C-012 | Storage paths and keys are both presentation data and legacy identity material. | Tongs assets owns them; Hammer migration hashes them; packages emit them. | Same-path replacement can silently alter meaning. | Treat as `StorageObjectKey`/locator evidence only; add same-path/different-ID regression. |
| S4C-013 | Signed/generated URLs sit beside media identity in Hearth view models. | Reference Visual maps storage key to `imageUrl`; other preview loaders expose URLs. | Cache or URL replacement can be mistaken for asset continuity. | Explicitly type URLs as ephemeral presentation fields. |
| S4C-014 | Hammer-to-Quench visual packets drop asset identity. | Packet visuals include `placement_id` and `asset_path`, not canonical asset ID/evidence. | Quench must guess or accept path authority. | Slice 4 packaging boundary must retain validated canonical ID or unresolved state. |
| S4C-015 | `HammerProgramPackageV1` names asset fields but provides no relationship envelope. | `thumbnail_asset_id`, `reference_asset_ids` are plain strings. | Package assembly can accept IDs without workspace/workpiece/kind proof. | Route through canonical resolver/readiness before production-current status. |
| S4C-016 | Editorial B-roll `asset_ref` binding state is not canonical-asset readiness. | `insert_broll` operations expose generic `asset_ref`; packet summarizes “resolved” bindings. | Local resolution may be represented as production-ready media. | Add canonical asset reference/readiness to placement authority. |
| S4C-017 | Asset scope model cannot yet express requested workspace-global reuse in `tongs.assets`. | Initial/current asset table has non-null `workpiece_id`. | Making it nullable could misuse null as unknown; leaving it unchanged cannot represent global assets. | S4-1 must first identify the existing brand/global asset authorities and decide an explicit scope model. |
| S4C-018 | Same-workspace/workpiece checks are often procedural rather than relational on derivative asset rows. | B-roll/Reference RPCs query asset with workspace/workpiece; some rows only FK `asset_id`. | Direct or future writers could bypass relationship intent. | S4-1 decides where composite FKs are possible after exact schema inventory. |
| S4C-019 | `supersedes_asset_id` may be misread as permission to follow “latest.” | Canonical assets encode supersession; downstream types do not lock non-substitution. | Historical A can silently become B. | Contract must state supersession never rewrites an existing reference. |
| S4C-020 | Manual Hearth visual-actionability IDs are client generated. | `createClientId` populates `asset_id` for manual B-roll/reference results. | Client identity can enter persisted package fields with an asset-shaped name. | Mark legacy-derived/unresolved; require Tongs registration before production placement. |
| S4C-021 | Active Hammer manual placement still creates media identity from a path. | Visual editing writes path into `asset_ref`, `asset_path`, and `storage_key`, then calls `deriveStableHammerVisualAssetId`. | New—not only historical—placements can create legacy-derived production IDs. | S4 implementation must switch new writes to canonical asset resolution before placement. |
| S4C-022 | Packaging logo/background choices can be selected by current path or first library item. | Hammer visual editing defaults logo to an existing path or `derivedSourceImageLibraryItems[0]`; background replacement hashes its selected path. | Packaging/effect media can be silently selected or locally identified without canonical authority. | Inventory now; later behavior work remains out of scope, but any production write must use canonical identity or unresolved readiness. |

## Stop-rule applications

- Do not rename any field in this register merely because its likely future type seems obvious.
- Do not backfill canonical identity from path, filename, URL, current candidate order, nearest timestamp, “latest,” local asset-map membership, or the only surviving asset.
- When exact semantics cannot be proven, retain the original value and classify it `unresolved` or `legacy-derived` with provenance.
